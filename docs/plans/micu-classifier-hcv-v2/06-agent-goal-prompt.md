## 已确定的部署条件

- 教师、改写、补全与隔离审核使用 Micu：micu_slb / gpt-5.6-terra。
- 学生使用 models/Qwen3-VL-4B-Instruct 原始权重，固定权重诊断，不 SFT。
- 使用已有正式 ViT-L 分类器，路径及来源核验要求见 05，不训练新模型。
- 仅本地 AgriNet v3 collection，使用现有 SigLIP2；不新增网页搜索。
- 三个模型工具：agrinet_classifier_predict、agrinet_classifier_expand、
  agrinet_rag_search。检索只开放 visual/semantic，Top-k 固定 3。
- 初始只给图像、问题、任务协议和公开运行状态，候选必须经分类器工具取得。
- 每个 query 图像在同一候选包中只保留一种 pattern，检查实际行为一致性。
- 教师、学生、审核的消息和记录隔离；私有标签不回流生成或改写请求。

不重新询问上述已确认选择。不得自行启动 T0、160 图探索、第二批采集、
MAE、分类器、OOF 或学生训练。首个 goal 的终点是工程与一次限定冒烟
报告，不是证明蒸馏收益；人工签核和正式训练资格留给下一阶段。

## 实施顺序

1. 将 05 的选择绑定为新的版本化 v2 配置与注册 CLI 入口；保留 v1。
   固定工具 schema、公开运行状态、实际 renderer、图像处理与终态。
   新入口必须能 show、dry-run，参数来自配置，不靠临时脚本隐式覆盖。
2. 补齐分类器单图适配、候选扩展与本地检索映射。保留原始返回及规范
   事件，不照搬旧 HCV 的强制检索次数、固定原始候选或文本-only 包装。
   visual 同图重复查询不能伪装成新证据，semantic 实际分支要记录。
3. 实现全局操作身份与预算账本、父子轨迹血缘、公开/私有请求隔离、
   pattern 实际行为检查、G1/G2 适配、审核和候选导出。请求前持久化
   intent，响应后记录原文、用量、延迟、状态；并发和恢复共享预算。
4. 先完成模拟端到端测试及实际学生 token/role/mask 验证，再核验
   checkpoint、fresh 图像、历史排除账本和检索图像隔离证据。不得
   用分类器训练图、dev/test 或未知交付图填满 32 图。
5. 真实依赖通过后，按注册流程 show、dry-run，执行最多四次能力检查，
   再运行固定的 32 图自然父轨迹及原始 4B 诊断。八格各四图，初始
   输入/工具可见性一致；学生不读取教师轨迹、审核标签或生成历史。
6. 对通过审核且有合法前缀的父轨迹，每格按 sample ID 顺序选最多
   一图，合计最多八图，各尝试一次 G1/G2；缺格不跨格填充。按 05
   确定 G2 前缀及剩余额度，不看补全结果后再挑前缀。
7. G1 固定事实和核心动作；G2 新调用必须实际执行，不复制原后缀的
   未来返回。T1a 保留相同有效 assistant 段的监督口径；T1b 两臂均
   只监督前缀后的有效 assistant 后缀。工具返回不监督。
8. 每条完成轨迹最多一次隔离私有审核，输出 accept/reject/human_review。
   审核失败不返回标签或原因让教师重写。各预览包独立保存且
   training_eligible=false，交付 Markdown/JSON 总报告和人工审阅索引。

不要逐图人工拼接推理模板。任务与协议可以有必要指令，模型生成的
自然原稿、改写和补全文本保持各自血缘。任何生成指令的真实模型调用
也占总预算；四次预留能力检查之外没有隐含的 prompt 搜索额度。

## 预算、资源与恢复

- Micu 全 goal 最多 340 次：父轨迹最多 256，八组衍生最多 80，
  能力检查最多 4。各阶段未用预算不能变成新增图像或额外衍生尝试。
- 单次输出最多 8192 token、timeout 180 秒，合计最多两个在途请求。
  默认 temperature=0、top_p=1；实际参数支持须核验，不能静默替换。
- 父轨迹每条最多 7 次生成、5 次 RAG、1 次私有审核；教师与衍生
  RAG 合计最多 200。G2 从前缀剩余额度继续，不重置计数。
- 学生固定权重诊断最多 32 条、224 次本地生成、160 次 RAG；
  单独记账，不训练、不增加 checkpoint 或重复评测挑最好结果。
- GPU 1 用于学生，GPU 2 用于检索与分类器；执行前核查占用，
  不抢占、不停止已有任务，也不自行换卡。
- 分类器每轨迹最多一次逻辑预测，最多一次有效扩展；缓存绑定图像
  和模型摘要，仍须通过模型的逻辑工具调用才公开候选。
- 按 progress-budget-v1 累计开放 0→1→3→5 次检索。去重、进展
  判定和拒绝状态按 05 执行，至少保留一次后续生成为最终闭合。
- 请求失败也计预算；超时、截断、错误响应和未知交付不自动重放。
  恢复先检查目的状态、原始账本和已完成产物，不另开目录绕过去重。
- 总请求上限不是费用上限。分别保存输入/输出 token、延迟、缺失
  用量与有依据的费用，不能隐藏拒稿或共享上下文的成本。

使用项目根目录 .venv/bin/agrinet 和 .venv/bin/python。保留 .venv_test，
不安装额外任务环境，不用 Slurm。短命令前台执行；长任务预览后用 CLI
的 --detach，按返回 PID、run_dir、状态和有界日志核验。
日志在 outputs/runs/<domain>/<experiment>/<run>/logs/，复用产物在
outputs/artifacts/。凭据只用于内存请求，不打印或写入配置、预览和日志。

实际学生 renderer、图像处理、role/token/mask。先模拟，再真实预检。

状态、原始/衍生/学生各自的账本与成本、审核决定、失败/排除索引、
模式覆盖、候选预览包、Markdown/JSON 报告及人工审阅入口。
区分工程验收、真实冒烟结果和正式训练资格，不能相互替代。

工程通过，预定 32 图真实尝试及许可操作状态完整落账且报告交付后，
才将本 goal 标记 complete。真实答错、审核拒绝或可衍生图不足八张
可以是有效实验结果，不要求补采，也不等待人工签核。父轨迹接受率
不等于训练资格；既有两轮稳定性和人工门槛留待下一阶段。

缺少 32 张合格图、关键资源不可用或未修复的工程错误导致主批次未
执行时，继续完成不依赖缺口的工程与证据核查，交付具体缺口；不能
降低目标后标为完成。遵循 goal 工具的阻塞规则，不在首次受阻时
擅自 blocked，也不在达到阻塞阈值后无限保持 active。

分块 apply_patch，每块做有界检查；传输中断后先核实已写入内容。
保持有信息量的进度更新，不输出空 final，不反复要求用户“请继续”。
研究记录和交接留在此独立目录；原始大产物放 outputs/。不自动 commit、
push、发送外部消息或清理用户数据。最后报告完成项、证据、剩余缺口
和下一阶段入口；不要暗中启动下一阶段。现在开始恢复现场并实施。

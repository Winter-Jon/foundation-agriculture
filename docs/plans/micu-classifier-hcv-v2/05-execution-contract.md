## 1. 目标、固定选择与边界

首个 goal：工程验证、32 张独立 fresh 图像的真实冒烟、最多八组 G1/G2
衍生验证、原始 4B 固定权重执行诊断，以及可复现的完整报告。

| 项目 | 已确认配置 |
| --- | --- |
| 教师/改写/补全/审核 | Micu，micu_slb / gpt-5.6-terra；分别记录请求与 prompt 版本 |
| 学生 | models/Qwen3-VL-4B-Instruct 原始权重，只诊断，不 SFT |
| 分类器 | outputs/artifacts/vision/openagri-v3-known-vitl-mae-v1/classifier-formal/model_best.pth.tar |
| 分类器依据 | 同实验 training manifest、label_map、预处理和训练账本；先验证摘要与来源 |
| 检索 | 仅本地 AgriNet，open_agri_v3_classes / open_agri_v3_images，已有 SigLIP2 |
| 样本 | 32 张，Open/Option × EN/ZH × disease/pest 八格各四张 |
| 衍生 | 最多八张已接受父轨迹，各一次 G1 整体改写与 G2 前缀补全 |
| T0 | 本 goal 不执行无候选/预注入候选的额外成对诊断 |
| 额外训练 | 不启动 MAE、分类器、OOF 或学生训练 |
| 人工交接 | 本地审阅报告；人工签核与正式数据资格留到下一阶段 |

首轮只接收经 SHA、来源组和近重复隔离核验的 fresh 图像；排除分类器
监督训练、dev/test 和历史禁止图像。MAE 无标签暴露单独记录。当前正式
ViT-L 是 107 类分类器，不为 P6 启动类别留出训练；冒烟不要求十种
pattern 全覆盖。无法取得 32 张合格图像时报告具体缺口，不自动补采、
改用 in_sample、伪造空排除账本或启动三折训练。

每 query 图像在同一候选训练包及所有混合入口中只保留一种 pattern。
按 [01-design.md](01-design.md) 检查实际触发条件、动作与证据，不只查标签。
正式 Unknown 不进 SFT；最终测试不参与路线、阈值或 checkpoint 选择。

## 2. 模型工具与部署协议

初始输入只有图像、公开问题、任务协议及公开预算状态。分类候选不免费
预注入，审核、文件系统、网页访问和数据库管理不作为模型工具。

| 工具 | 输入/行为 | 公开返回 |
| --- | --- | --- |
| agrinet_classifier_predict | 当前 query_image；每轨迹最多一次实际推断 | 预测引用、Top-3 名称与实际分数；内部保存 Top-5 |
| agrinet_classifier_expand | 已取得的预测引用、非空理由；最多一次有效扩展 | 同次 Top-5，不再次推断 |
| agrinet_rag_search | query、retrieval_type、image、rationale；visual/semantic，Top-k 固定 3 | 公开证据、引用 ID、实际分数与来源 |

执行器绑定真实图像路径，模型只使用 query_image 或合法无图模式。
visual 必须使用当前图像，semantic 使用公开文本且不附图。模型不控制
filter、融合权重或其他模式；不得对外声明支持却静默丢弃的参数。公开
工具结构、内部请求与原始响应的映射要有夹具。分类分数不是 Known 概率，
不与检索分数相加，不因高分直接放行。

冻结实际数据库路径、collection 内容版本、编码器与返回转换版本。
允许检索 Top-5 外的类别，不继承旧 HCV 的固定候选集合或最少检索次数。
排除 query 自身及禁止重叠的图像证据；无法证明隔离时报告缺口。
现有 visual 不按 query 文本改变召回：同图仅改措辞不算新检索。现有
semantic 可先走候选比较、再回退文本检索；记录实际分支，不称为纯向量搜索。

教师原生调用保留规范事件和原始返回；学生推理与候选导出共用现有 Hermes
兼容渲染路径并核验实际 token/role/mask。最终闭合沿用项目合法答案格式，
不新增独立的最终回答业务工具。Open 返回名称或 INSUFFICIENT_EVIDENCE；
Option 返回合法字母或该标记。Known/Unknown 是私有评分角色，不能把
服务故障自动变成 Unknown；具体评分沿用冻结任务定义。

## 3. 操作身份、衍生与私有审核

每图预先建立父轨迹、学生诊断、能力检查、衍生和审核操作清单。全局
contacted 管理按图像与许可操作核验，既允许本合同明确安排的操作，也
不允许历史 rejected/retired/unknown_delivery 借新 ID 重放。未知交付
图像的未执行依赖操作先隔离，其他未受影响图像可以继续。

最多四次 Micu 能力检查使用预定批次图像，记录操作身份，不增加独立
图像数，不用其输出冒充父轨迹；覆盖连通性、视觉输入和格式能力。

父轨迹先经公开校验和一次隔离私有审核。各任务格按固定 sample ID 顺序
选择一张已接受且有合法补全前缀的图，不按得分、长度或衍生结果挑选。
某格不足不跨格填充，衍生数量允许少于八。优先在首次分类器返回后
截断；没有分类器调用则用首次 RAG 返回后的边界；无工具前缀则跳过。

G1 固定工具事实、次序和核心行为，模型整体整理公开 assistant 表达；
禁止未来证据前置。G2 只看公开前缀，不看原后缀，新增工具调用实际执行，
按前缀剩余额度约束；T1b 的原后缀/G2 两臂都只监督后缀，T1a 的
G0/G1 则监督相同类型的全部有效 assistant 段。二者按 T1a/T1b
分别记录，不能将 G2 的新增证据收益归因于文字改写。

每条完成轨迹最多一次隔离 Micu 私有审核，结果为 accept/reject/human_review。
原审核器只支持二值结果，实施时扩展，不静默丢弃 human_review。私有
标签与审核原因不返回生成器修正。相同模型的隔离审核仍有相关偏差，
报告说明其局限；本 goal 不循环请求第二次模型审核补齐分歧。

G0/G1/G2 分别导出预览包，保留父子血缘、选择/排除理由与模式变化。
所有预览包 training_eligible=false；不混为同图多模式训练数据。

## 4. 全局预算与资源

| 项目 | 硬上限 |
| --- | ---: |
| 32 条父轨迹 Micu | 256 次：每条最多 7 生成＋1 审核 |
| 八组 G1/G2 Micu | 80 次：每组 G1 最多 1 生成＋1 审核，G2 最多 7 生成＋1 审核 |
| 能力检查 Micu | 4 次 |
| 全 goal Micu | 340 次，所有进程及恢复运行共享上限 |
| 教师与衍生 RAG | 200 次：父轨迹 160，补全最多 40 |
| 学生诊断 | 每图一次，共最多 32 条轨迹、224 次本地生成、160 次 RAG |
| 单次 Micu 输出 | 最多 8192 token |
| Micu 并发/超时 | 所有类型合计最多 2 个在途请求；单次 180 秒 |
| GPU | 学生用 1；检索与分类器按需共用 2 |

G2 实际额度按前缀已消耗的生成、RAG、分类器调用和扩展状态扣除，不能
重置。八组的 80 次是保守上限，并非每组必须消耗十次。能力检查、制备
指令生成、修复或其他 Micu 操作都占总预算：数据请求之外只预留四次，
不得暗增 prompt 搜索预算。失败尝试与未知交付计入请求消耗。

默认解码 temperature=0、top_p=1，用于本轮复现，不声称它是最佳蒸馏
分布。能力检查核验服务支持；不支持时记录差异，不静默换模型或参数。
学生诊断采用同样输出长度上限与确定性解码。输入超出实际可用上下文时
记录超限，不静默裁剪图像、前缀或工具证据。

请求上限不等于金额上限。分别记录输入/输出 token、延迟、缺失用量和
服务提供的费用；没有可靠价格依据时不编造金额。学生、教师、衍生及
共享检索成本分别统计。同次分类器结果可按图像/模型摘要缓存，但公开
可见性只能在实际逻辑调用后开启；分别记录逻辑调用、物理推断和缓存命中。

运行前检查 GPU 1、2 的现有进程与占用，不抢占、不停止其他任务，不
自行换卡。资源被占用时完成不依赖 GPU 的工作，保存可恢复状态并报告。
所有程序日志遵循 outputs/runs/<domain>/<experiment>/<run>/logs/，
复用产物置于 outputs/artifacts/；凭据仅在内存中使用，不进日志或预览。

## 5. 累计检索控制器 progress-budget-v1

模型提出下一次检索，控制器执行限制，不另设模型可调用的预算申请工具。
初始累计检索额度为 0，首次合法请求开放至 1；超过档位时只允许 1→3、
3→5，升级后保留原有消耗。升级原因和余额随工具运行状态返回并入账。

放行要求：合法且尚未执行的查询、非空公开理由、剩余生成额度可容纳
至少一次后续闭合。不读取真实标签、预测对错或目标 pattern。文本重复
按规范化后的 query、模式和图像身份检测；同图再次 visual 无论措辞
如何都属于重复。不声称此检查能识别所有语义改写式重复，报告中保留
原文供独立分析。重复/无效请求不执行检索，但已发生的生成请求照计。

检索进展按新证据 ID 或内容摘要记录。连续两次实际检索没有新增证据
则拒绝继续检索，要求完成判断或证据不足停止。新增 ID 只是可复现的
控制信号，不自动代表有效区分证据；有效性在审核/报告中另行判断。

分类器调用、候选扩展、格式错误以及被拒动作同样消耗已发生的生成
请求。生成余额只剩一次时只允许最终闭合，不强制用满五次 RAG。控制器
终止必须标为控制器行为，不能伪装成模型自主停止。

请求先落盘 intent，响应后保存原始结果和状态。超时、断连、截断及
错误响应不自动重放；恢复先读目的状态。未知交付只隔离受影响图像及
依赖操作，其他图像可继续；服务/协议的系统性故障应终止批次并报告，
不得用未执行条目冒充完成的 32 图冒烟。

## 6. 测试、报告和 goal 验收

工程至少验证：同图实际行为冲突、私有/未来证据泄漏、工具参数与返回
映射、分类器版本与身份绑定、扩展复用、visual/semantic 重复请求、
预算累计及闭合保留、G1 事件保持、G2 前缀及后缀 mask、并发去重、
中断恢复、超时/截断、真实学生 renderer/图像处理/role/token mask。
先通过模拟端到端验证，再做注册 CLI show、dry-run、真实依赖预检。

报告必须包括：32 图和全部许可操作的状态；父/衍生/学生分开的结果、
调用与用量；审核决定和人工审阅索引；pattern 覆盖与冲突；失败/拒稿/
未执行原因；原始/衍生血缘；候选导出及明确的资格标记。交付本地
Markdown 总报告和 JSON 汇总，不发送外部消息。模型生成错误和审核
拒绝保留在分母，不能只报成功样本。

首个 goal 完成须工程验证通过、预定 32 图真实尝试及许可操作状态完整
落账并交付报告。有效执行后的答错、拒稿或衍生不足八组不要求补采；
无需等待用户人工签核报告。未修复的工程错误、缺失账本、资源/输入
不足导致未执行的主批次不能标 complete。按 goal 工具规定处理阻塞，
不能自行降低完成目标，也不能为完成目标增加批次。

正式训练仍保留现有独立两轮稳定性及人工门槛。已知旧 v13 检查包括
每轮 32 图、接受至少 31 图、零关键错误、规则一致性 1.0、八格覆盖，
并检查两轮合并的必需状态；这些不是本次冒烟 goal 的成功率门槛。v2
状态与旧状态的资格映射留待下一阶段，不自动授予训练资格。

本轮后续执行不得自动启动 160 图探索、SFT、第二批或外部提交。缺图时
先完成工程和明确缺口，不能宣称真实冒烟已经完成。执行入口与机器可读
v2 配置由下一 agent 实现并核验；现有 v1 配置仍只是离线预检入口。

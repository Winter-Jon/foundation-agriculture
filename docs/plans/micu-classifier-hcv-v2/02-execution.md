# 执行顺序、实验对照与验收

状态：规划，不是已注册的采集或训练授权。设计见 [01-design.md](01-design.md)，
生成方法与路由见 [03-generation-and-routing.md](03-generation-and-routing.md)。

## 首轮部署条件先冻结

首轮建议固定为一个可选工具学生：初始只看图像、公开问题、任务协议和
公开预算状态，可以直接回答，也可以调用分类器或检索。分类候选不预先
注入；只有实际调用分类器后才显示 Top-3，扩展复用已保存的 Top-5。
在 E0 固定学生 checkpoint、图像处理器、工具接口、renderer、解码参数
和停止约定。此处是 v2 的执行起点，不修改现行 v1 的成对候选诊断合同。

先用固定权重学生与教师各自做小规模诊断，确认动作、返回和最终闭合能
工作；教师生成候选父轨迹时采用同样的工具可见条件。学生诊断请求另设
上限和账本，不能计作教师合格数据或占用后续测试作模型选择。

T0 的无候选/预注入候选卡继续作为独立候选价值对照。其图像可用于配对
诊断，但预注入候选卡的轨迹不直接进入本工具学生主训练包。不同输入
条件分别标 deployment_condition；后续改变条件必须重新冻结采集协议。

## 先验证可运行性，再比较工艺和优化策略

| 阶段 | 工作与交付 | 进入下一步的条件 |
| --- | --- | --- |
| E0 部署、协议与数据准备 | 冻结初始可见输入、checkpoint、工具 schema、renderer、主 pattern 行为规范和预算；本地夹具 | 身份隔离、事件血缘、实际 token mask 和终态检查通过 |
| E1 固定权重路由冒烟 | 32 张独立新图，八格各四张；在部署条件下检查模型动作与执行闭合，另列候选价值诊断 | 工具调用可运行、两类诊断不混淆、失败完整记账；不取得训练资格 |
| E2 数据工艺探索 | 最多 160 张新图，P1–P10 各争取 16 图；检查 G0/G1 表达与 G2 补全可行性 | 报告质量、模式一致性、缺口和成本；冻结候选工艺与比较协议，不选择学生赢家 |
| E3 独立稳定性与人工确认 | 各拟进入训练的候选工艺取得相应独立批次证据，沿用两轮稳定性和人工门槛 | 正式资格文件通过；父轨迹资格不自动传递给衍生工艺，探索不能替代此步骤 |
| E4 学生小规模 SFT 对照 | 合格图像、固定学生和训练口径；表达与补全分别比较 | 此时才依据开发集收益、Direct/Unknown 保留和成本选择工艺；无效则不选 |
| E5 路由与预算对照 | 在选定数据工艺上比较固定/动态路由、固定/递增预算 | 明确效应来自模型还是控制器，成本收益可复现 |
| E6 扩采与最终评测 | 冻结路线、阈值、checkpoint 选择和数据版本 | 最终测试只作最终结果，不再据其调参 |

E1/E2 规模沿用原计划，按独立图像计数；不能把同图改写、语言变体或
重复采样算成新增图像。E2 不要求失败样本反复补到每格恰好 16，缺口
公开报告。P10 仅 Open。正式 Unknown 不入 SFT；模拟 Unknown 从 Known
留出，分类器监督必须排除相应类别，并记录 MAE 无标签暴露。

160 图是工艺探索上限，不是十种 pattern × 八个任务格 × 多工艺 × 多
随机种子均有足够统计功效的保证。E2 主要发现协议缺陷、估计接受率和
成本；先报告实际可比较图像数及每组覆盖。交集太小时，优先完成 G0/G1
对照，把 G2 限于少量前缀可行性检查，不从微小指标差异选赢家。
E3/E4 所需新样本规模按预先定义的最小有用效应、风险容忍度和独立开发
数据的不确定性估算；不足则报告不可判定，不能用更多同图变体增加 n。

## 每张图的可恢复数据流程

1. 建立 image_group_id、SHA、来源组、近重复组和固定 split，先排除历史
   rejected/retired/contacted/unknown_delivery 与 dev/test 重叠。核验
   fresh 或三折 OOF 分类器预测、checkpoint 和实际训练清单血缘。
2. 在私有侧记录 target_pattern 和采样桶；公开生成只看图像、问题、
   实际候选及真实返回。教师固定 Micu，模型/服务/prompt/参数分别版本化。
3. 获取自然父轨迹，所有请求先记录 intent、后记录结果；原文、用量、
   超时、截断及最终状态保留。有效原稿优先成为 G0 对照候选。
4. 对预先列入衍生实验的已接受父轨迹，按冻结配置制备 G1 改写或 G2
   补全。独立请求与账本；不将已拒绝图像通过衍生 ID 重新提交。
5. 先做公开格式、事件和因果检查，再做隔离私有审核。审核只能接受、
   拒绝或送人工；不把真实答案反馈给生成器不断修正。
6. 根据实际核心行为确定 primary_pattern，保留 observed_patterns 诊断
   标签；按同图分组选择合格记录。主模式冲突不以强改标签解决。
7. 转换为学生实际可见输入和监督，检查图像处理、消息角色、工具 token、
   最终闭合与实际 loss mask；原始事件和改写指令不混入学生输入。
8. 输出候选包、拒绝索引、缺口报告与资格状态；通过正式 gate 后才进入
   SFT。对全部混合训练入口再次检查同图只有一个 primary_pattern。

必须留存的私有制备字段：parent_trace_id、derivation_id、generation_method、
prefix_id/截断位置、原始及衍生内容摘要、工具事件引用、审核版本/结果、
primary_pattern、observed_patterns、选中/排除原因、转换版本。执行字段
另含模型快照、解码参数、request ID、状态、token、延迟和预算余额。
训练导出明确区分 prompt、assistant target 和被 mask 的上下文。

## 预算：原轨迹与衍生制备分开计算

原始单轨迹保留最多 5 次 RAG、7 次 Micu 生成、1 次私有审核。v2 的
主部署轨迹按每图一条计：32 图上限 160 RAG、224 生成、32 审核；
160 图上限 800 RAG、1120 生成、160 审核。分类器最多每轨迹一次
推断，另记 GPU 时间与延迟；这些上限不是必需消耗。

若同时执行 T0，另设 D 条诊断轨迹；总原始轨迹数为 N + D，Micu 上限
为 8(N + D)，RAG 上限为 5(N + D)。例如 32 图额外各跑两个 T0 视图，
则 N=32、D=64，共 96 条教师轨迹，最多 768 Micu 请求和 480 RAG；
不能仍按旧双视图 64 条收费。诊断复用必须输入和配置完全相同并明确
引用同一已完成请求，否则单独计费。学生冒烟、prompt 搜索与能力检查
也另列预算，不包含在上述教师公式中。

建议 E2 仅对预先选定的每图一个父轨迹尝试一次 G1 和一次 G2；这是成本
起点而非现行授权。G1 建议上限 1 生成 + 1 私有审核；G2 上限为父轨迹
截断点剩余的原始生成/RAG 额度，加 1 独立审核，不重置为全额。
父前缀原有成本记一次，G2 实际新调用另计；每个训练包同时报告总制备成本
及共享成本的分摊口径。所有衍生操作仍需新增、版本化的实验配置才能执行。

例如 160 个父轨迹各尝试 G1/G2，按 G2 最宽 7 生成 + 5 RAG + 1 审核
作保守额外上限，则衍生部分最多 1280 生成、320 审核、800 RAG；与
160 条主部署父轨迹相加最多 2880 Micu 请求、1600 RAG；再加 T0 的
8D 次 Micu 和 5D 次 RAG 上限，实际按截断位置进一步收紧。此处
不安排 E2 默认全跑 T0 双视图；追加诊断须在该批配置中显式计入。不得
把 160 张图误记为 160 次请求，也不能隐去被拒稿成本。

## 对照设计：每次只改变一个主要因素

| 对照 | 固定项 | 变化项 | 主问题 |
| --- | --- | --- | --- |
| T0 候选价值 | VLM 权重、图像、问题、检索接口 | 无候选、候选名称、候选及分数；分类器单独预测另列 | 正确修正是否超过错误改判 |
| T1a 表达工艺 | 配对合格图像、主 pattern、工具参数/返回/次序、学生初始化、renderer、训练口径 | G0 原稿、G1 整体改写 | 相同事实和动作下，改写是否更易学 |
| T1b 补全工艺 | 合格父轨迹、公开前缀及选择规则、学生初始化、工具接口、训练口径 | 原有后缀、G2 新补全后缀 | 新后缀及实际新证据是否改善数据工艺，收益值不值成本 |
| T2 指令方案 | 选定工艺、数据、模型与工具能力 | 现有合法协议、模型提出的统一简洁协议 | 统一指令是否减少格式和行为冲突 |
| T3 路由策略 | 指令、学生权重、工具服务和全局成本口径 | 固定路由、公开状态驱动路由 | 在风险不增加时减少无效调用 |
| T4 工具预算 | 路由实现、图像、工具和生成上限 | 固定额度、0→1→3→5 累计升级 | 是否改善质量/成本曲线 |
| T5 采样策略 | 选定工艺、预算、资格规则 | 随机采样、约 1:1 普通/困难 | 同成本是否提升更多 |

T1a 仅用 G0/G1 均通过且行为一致的交集，不因 G2 失败再缩小这组样本。
两臂监督所有相同类型的有效 assistant 段，工具返回均为上下文。首轮
保持工具事实与核心决策一致，不改变主 pattern；改写的影响是表达变化。

T1b 单独建立 G0/G2 配对，固定截断点选择规则，不能看到补全结果后挑
最有利的前缀。主比较两臂都只监督该前缀之后的有效 assistant 后缀，
共享前缀只作上下文；完整轨迹训练是后续独立对照。G2 可以取得新证据，
所以其总收益包含动作/证据变化，不能归因为“措辞更好拟合”。报告新增
查询、有效证据、终态变化及额外调用成本。主 pattern 改变的记录退出
此配对比较并报告缺口，不强行改标签。

每项同时报告完整父轨迹池的接受率、淘汰原因、图像/类别覆盖和单位
合格样本成本；交集性能只代表双方可生成合格监督的子集。补充等制备
预算的各工艺独立包比较用于端到端效率，不能和配对比较混为同一结论。

主训练预算同时冻结 optimizer 更新数、实际监督 token、图像曝光及硬件
计算口径；长度不同可能无法使这些量全部相等。预先指定 token/计算匹配
为主结果，等图像曝光为辅助结果，记录残余差异。不能通过重复采样短稿
而不报告曝光次数来宣称公平，也不能让较长稿自动获得更多 loss 权重。

checkpoint 选择使用独立开发集。至少在确认候选上做多个预先固定的随机
种子，报告效应和区间；探索阶段单种子结果仅用于排除明显无效方案。
先做 E1 可运行性诊断，再检验工艺，最后优化路由/预算；可运行性通过
不等于路由策略已经最优。避免同时变更后无法解释收益来源。

## 验收指标与停止条件

- 数据：主 pattern 冲突、泄漏、伪造工具事件必须为零；报告每格覆盖、
  同图总权重、可审核轨迹比例、改写事实变更率和截断比例。
- 学习：验证集 NLL 只在相同公共目标/同口径 token 上比较；观察等预算
  下的任务指标、收敛曲线、种子方差及长短轨迹差异，不只看训练 loss。
- 任务：Known Macro-F1、Unknown 准确率/误归 Known、正确修正、错误改判、
  Direct/RAG 保留、终止正确性、可执行工具调用和无效检索占比。
- 成本：每图生成/RAG/分类器调用、实际 token、延迟、失败和全部衍生/审核
  成本；同时报告达标率与成本曲线，不能只统计成功轨迹。
- 不确定性：以独立图像或更保守的来源组聚合置信区间，同图变体不增加 n。
  区分语义 Unknown、证据不足、预算耗尽与服务错误，分母包含执行失败。

开发阶段预先确定 Unknown 误归风险和 Direct 退化的可接受增量，并记录
依据；本规划不虚构已有数值阈值，也不把现行稳定性门槛降为“平均正确”。
若改写更易拟合但自主执行或 Unknown 更差，则不推进；若预算增加只有
轨迹更长、没有新证据，优先改进检索和停止规则。

## 实施交付与当前缺口

下一轮工程按依赖顺序交付：分组及主模式检查器 → 共用 renderer/mask
夹具 → 父子轨迹和预算账本 → 原稿/G1/G2 适配器 → 独立审核与导出 →
采集及学生对照报告。离线预检和现有请求账本可复用，但不代表这些模块
已存在。夹具需包含未来证据泄漏、工具返回被改写、预算重置、同图跨包
混合冲突、截断及未知交付恢复等反例。

当前仍缺真实候选清单、完整历史排除账本、同图衍生操作的新配置与正式
资格证据。当前工作仅形成规划，不启动请求或训练，不更改已有教师、
数据边界与实验入口。原始单一 pattern 实验编号可后续补入证据文件，
不以尚未提供编号为由推翻用户已经确认的约束。

# 生成、改写、补全与动态路由

状态：候选数据工艺，尚未验证优劣。每个训练包均遵守每 query 图像一种
primary_pattern；方法依据及其局限见 [04-evidence.md](04-evidence.md)。

## 三种生成方式，分两项比较

| 方式 | 模型实际接收的信息 | 输出及用途 | 主要风险 |
| --- | --- | --- | --- |
| G0 自然原稿 | 图像、公开问题、可用工具及本次实际返回 | 原始有效轨迹，作为基线 | 冗长、局部重复或格式不稳定 |
| G1 整体改写 | 图像、公开问题、完整可见原轨迹和真实事件账本 | 模型整体整理 assistant 文本，保留可追溯事件 | 后见之明、删掉重要反证、语言漂亮但难执行 |
| G2 前缀补全 | 同一任务截至指定时刻的公开前缀 | 模型从该状态继续生成、实际调用工具并完成 | 前缀偏差、虚构未执行的工具返回、隐含提示答案 |

先冻结 [执行文档](02-execution.md) 的工具可选部署条件，再制备上述数据。
G0/G1 是相同事实、动作下的表达对照；原后缀/G2 是同一公开前缀下的
补全工艺对照，可能改变后续动作和证据。两者不视为完全对称的三臂实验，
也不要求三个工艺取共同交集。G2 的新证据收益与文字易学性分别解释。

不要求完整概率。模型自然生成的样本经过验证后形成经验分布；不同生成
工艺、解码参数和筛选条件分别记录。不要把“自然”定义为必须零温度或
必须很长，也不把某个教师推荐温度照搬给 Micu。先做小规模参数检查，
选定可复现设置后冻结，主实验不同时改变温度、提示词和数据工艺。

G0 不逐段人工拼接视觉观察、候选分析或固定句式，人工只维护任务、协议
和数据边界。G1 的改写请求也只描述约束与目的，不指定每张图应当如何
思考或最终属于哪个类别。名称规范化、schema 校验等确定性转换可以保留。

## 整体改写如何保留真实过程

完整轨迹是接口实际返回的可见消息与执行事件，不是假定可取得模型内部
全部思维。G1 看完整记录有利于整理一致性，但因此生成的文本是事后衍生
监督，不能再称为原始在线决策。原稿永久保存，改写稿另有 parent_trace_id。

首轮固定实际工具调用的参数、返回、次序和 ID，只允许改写 assistant 的
表达与可由当时证据支持的解释。不得把后来检索到的类名、区分性特征或
最终答案植入先前决策。已经从图像观察到的公开特征可保留，不因其后来
得到验证而误判为泄漏。检查按证据来源和可见时间进行，不只是关键词匹配。

若改写希望省略一次调用、改变查询或走另一条路线，这已是新策略：必须
从相应公开状态重新执行，取得新的真实返回，不能直接替换旧 tool 消息。
若只是解释摘要，可作为非策略监督的独立衍生臂，不能宣称学生学到了原
工具策略。原稿与改写稿的事实差异、删除内容和引用映射都留在审计报告。

独立验证分两层：确定性检查事件一致性；隔离审核检查视觉事实、因果
可见性和结论。审核拒绝后不把私有答案返给改写器反复修正。出现依赖
未来证据的前段文本时，优先淘汰该改写稿，不能仅改一个标签让其过关。

## 前缀补全如何贴近部署状态

优先从经审核的自然原稿中选择边界：初始判断后、分类器返回后、一次真实
检索返回后。固定 prefix_id、截断位置和全部可见消息，移除原稿后缀、
审核标签、目标模式提示和答案暗示。补全模型不知道原稿之后发生了什么。

新增工具调用必须通过执行器，原来的未来返回不能作为新调用的结果。
模型如果只生成解释而没有实际工具动作，要按相应监督类型记录。首轮
只用教师前缀；学生生成前缀再由教师继续可留作后续暴露偏差实验，不能
仅凭前缀补全就称为已经实现 on-policy distillation。

补全有两种训练口径，实验前选定：保留合法前缀并只监督新增 assistant
后缀，或对审核通过的完整衍生轨迹监督所有有效 assistant 段。无论哪种，
均记录 actual_loss_mask；不监督工具返回。后缀专训不能被误计为整条轨迹
都获得了梯度，数据量比较采用实际被监督的 token。
首轮 T1b 采用后缀监督，两臂共享前缀且 mask 相同类型的段落；比较完整
轨迹监督另行安排，避免把 mask 差异误认成补全收益。

G1/G2 产生额外生成和审核成本，而且当前历史 contacted 排除规则不能
通过更换衍生 ID 绕过。首轮先使用本地夹具；真实同图衍生请求须在新实验
配置中显式列出父轨迹、预授权衍生操作、请求上限及独立账本。只允许对
这一批新采集且已接受的父轨迹作预定衍生；不开放历史 rejected、retired、
unknown_delivery 重放。当前 v1 配置没有这些授权字段，不直接执行。

## 统一 prompt 的目标与生成流程

先统一语义和训练/部署协议，而非人工写一大段规定所有思维步骤的 prompt。
以合格开发轨迹、工具 schema、终止规则及信息可见性约束为材料，让模型
提出少量简洁指令候选；不向其提供测试集或逐图私有答案。开发集比较后
冻结一个协议版本，用同一 renderer 编码 SFT 和推理消息。

部署 system prompt 只说明任务与可选能力，不透露某图应选的 pattern、
难度桶或路线。改写/补全的元指令属于制备请求，不进入学生训练上下文。
工具返回属于外部证据，不得成为更高优先级指令；检索中的提示注入也是
协议夹具应覆盖的失败情形。

若教师服务或学生模型要求不同模板，保留各自合法的传输格式，保证学生
训练与部署一致，并验证语义等价；不强行让所有教师使用同一 system 消息。
DeepSeek-R1 的特定使用建议也不是 Micu 的默认配置。统一 prompt 本身仍需
对照验证，但训练/部署不互相矛盾属于必须检查的工程条件。

## 动态路由：模型提出动作，控制器执行边界

候选动作包括：直接回答、调用分类器、扩展已保存候选、检索、继续核对、
证据不足停止。Unknown 是语义判断，INSUFFICIENT_EVIDENCE 是证据状态，
工具故障是执行状态，三者不互相替代。路由决策不得读取私有真实类别、
target_pattern、预测对错或审核结论。训练包中的 pattern 在事后独立审核
时确定，不能通过隐藏难度标签事先告诉模型“现在该纠错”。

公开状态建议仅包含：已使用/剩余工具预算、真实候选卡、已有证据引用、
未解决的视觉冲突和工具可用性。是否增加预算由这些可观察信号决定，而
不是“私有答案不对，再给一次机会”。困难定义也不只看教师自报置信度。

| 可观察情况 | 候选动作 | 要验证的风险 |
| --- | --- | --- |
| 视觉特征足够且不存在关键冲突 | 直接回答或低成本确认 | Direct 路由是否吸收 Unknown；不能仅看分类高分 |
| 视觉近邻难区分，尚无分类结果 | 调分类器并核对 Top-3 | 分数和排序是否造成锚定 |
| Top-3 缺乏支持，但尚有未看候选 | 显式扩展至 Top-5 | 扩展是否提供实际区分价值 |
| 候选有冲突，存在可检验的区分特征 | 检索该特征或另一公开假设 | 搜索词是否偷带私有正确类 |
| 已有检索重复、无关或不能消除冲突 | 换查询、换证据来源或停止 | 低质量重复调用被误计为努力 |
| 证据已充分，或图像本身无法支持进一步判断 | 完成回答或证据不足停止 | 强制多调用、强制给具体病名 |

首轮可使用可解释控制器约束可用动作，模型仍自然生成动作和理由。若
控制器决定了是否扩容，不能把扩容收益全部归因于学生学会路由；评测需
同时报告控制器作用及模型选择。下一步才比较模型自主提出扩容的版本。

## 按需要升级预算：0 → 1 → 3 → 5 是候选档位

这些数字是本项目待检验的成本方案，没有官方资料证明它们最优。0 表示
尚未调用检索，1/3/5 为同一轨迹累计允许的 RAG 次数，而非分阶段重新
发放 1+3+5 次。每次升级都记录此前消耗、原因、控制器版本和剩余额度。

建议升级条件：当前证据不足且有未验证的具体假设、新查询有可能提供
区分证据、全局预算仍允许。不因没有答出私有标签升级。一次无效检索不
必立即停止；连续无新增信息时应降低继续调用优先级。判定阈值在开发集
冻结，记录停止是证据充分、证据不足、预算耗尽还是执行故障。

原有每轨迹上限仍是 5 次 RAG、7 次 Micu 生成、1 次私有审核；首次
视觉判断、生成查询、公共协议修复和最终闭合都消耗生成请求预算。想用
满 5 次检索不保证还能容纳所有其他步骤：控制器必须检查剩余生成额度，
优先保留最终闭合请求。预算告知可随正常工具返回附带，不额外创造不计费
的“调度轮次”。格式错误和失败尝试也纳入实际成本，未知交付不自动重试。

分类器新增为独立工具时，建议每轨迹一次实际推断，Top-5 扩展复用同次
输出；其上限、GPU 时间、延迟与缓存规则需新增配置并冻结，不暗算为免费
RAG。预先提供候选卡与按需调用分类器是不同输入条件，不能直接混成同一
成本对照。教师选择路由时若总能看见免费候选，学生部署却需主动获取，
必须重新采集与部署一致的轨迹。

为保证学生知道何时能调用工具，预算与工具可用性作为公开运行状态进入
训练和部署。不能把执行器在幕后强制停止的结果伪装成模型自愿停止。
budget_exhausted 只保留为终态记录，是否训练沿用既有资格规则。

## 单一 pattern 的落点

采集期间可以观察多个候选行为，最终只按完整可见轨迹保留一种主 pattern。
“先检查后纠错再停止”本身可以是一种完整模式，不必为了固定模式拆散
因果过程。同图衍生稿若实际转成另一核心模式，则不进入该图已选 pattern
的训练包；保留作诊断或在独立实验包中研究，不能靠换标签混入。

原有成对无候选/有候选视图继续用于候选价值诊断，但不自动把两条都入训。
v2 主部署轨迹要求候选经实际分类器调用后可见；T0 预注入候选的视图
单列诊断账本和费用，不直接替代这条轨迹。小规模固定权重路由诊断在
工艺探索前完成，后续再系统优化路由与预算。
筛选规则在开发阶段冻结，以证据有效性和主模式一致性为准，不能用最终
测试成绩、目标配额或“挑出碰巧答对的一条”来声称在线路由性能。

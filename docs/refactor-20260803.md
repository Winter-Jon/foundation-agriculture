# RAG/VLM 项目重构计划

Status: Approved

## 1. 目标与原则

本计划将写入 `docs/refactor-20260803.md`，作为重构前的审阅基线。文档获批前不移动代码、不迁移产物、不删除旧入口。

本轮聚焦当前 RAG/VLM 主线，覆盖：

- 数据准备与 VLOOM 教师数据生成
- Milvus 索引、检索服务和 RAG 蒸馏
- VLM SFT、模型导出与评测
- 实验注册、命名、运行清单、产物布局
- `.venv`、uv 依赖锁定和 A800 GPU 运行环境
- 本地运行入口与双语使用文档

暂不重构 `vision/pretrain`、MAE、FocusNet 等视觉预训练代码；它们只复用新的公共运行与实验规范，不在本轮迁移。

核心原则：

- 用户只需记住一个根命令 `agrinet`。
- `data`、`rag`、`vlm` 是职责清楚的一级 subcommand。
- Python 模块提供稳定接口，CLI 只负责参数解析和编排。
- 本地运行器只负责进程生命周期和启动 CLI，不承载业务逻辑。
- 实验名称表达研究意图，不把学习率、epoch、长度等全部塞进文件名。
- 每次运行生成不可变 manifest，保证配置、代码、输入和产物可追溯。
- 旧入口直接切换，不保留兼容包装；有效实验登记后删除重复旧脚本。
- 第三方源码与项目代码隔离，项目代码不得从第三方框架内部模块随意导入。
- 根目录以及 data、rag、vlm 三个域分别维护 `README.md` 和 `README_CN.md`。

### 2.2 CLI 接口

规范入口为：

```text
agrinet
├── data
│   ├── list
│   ├── show EXPERIMENT_ID
│   ├── prepare EXPERIMENT_ID
│   ├── generate EXPERIMENT_ID
│   ├── convert EXPERIMENT_ID
│   ├── validate PATH
│   └── submit EXPERIMENT_ID
├── rag
│   ├── list
│   ├── show EXPERIMENT_ID
│   ├── index build EXPERIMENT_ID
│   ├── index check EXPERIMENT_ID
│   ├── search EXPERIMENT_ID
│   ├── serve EXPERIMENT_ID
│   ├── distill EXPERIMENT_ID
│   ├── validate PATH
│   └── submit EXPERIMENT_ID
└── vlm
    ├── list
    ├── show EXPERIMENT_ID
    ├── train EXPERIMENT_ID
    ├── export EXPERIMENT_ID
    ├── evaluate EXPERIMENT_ID
    ├── inspect RUN_OR_MODEL_PATH
    └── submit EXPERIMENT_ID
```

统一约定：

- `list` 和 `show` 只读取实验注册表。
- 本地执行命令负责调用 Python service 层，不直接拼装散落的 shell 命令。
- `submit` 读取实验关联的 runtime profile，在本机以前台或显式 `--detach` 模式启动统一 CLI。
- 本地后台进程调用 `agrinet <domain> <operation> <experiment-id> --run-id ...`，并把 PID、状态和日志记录到 run 目录。
- 所有命令支持 `--config-override key=value`，override 必须写入 resolved config 和 run manifest。
- 所有命令以非零退出码表示失败，并输出一行明确的错误摘要和 manifest 路径。
- API key 只从环境或已有凭据工具读取，绝不进入配置、manifest 或日志。

CLI 使用 Typer 实现，并通过根 `pyproject.toml` 暴露 `agrinet` console script。

### 2.3 Python 公共契约

以下类型构成稳定接口，CLI、本地进程编排和各域实现均依赖它们：

- `ExperimentSpec`
  - `id`
  - `display_name.en`
  - `display_name.zh`
  - `domain`
  - `task`
  - `description`
  - `components`
  - `runtime_profile`
  - `inputs`
  - `outputs`
  - `tags`
  - `lifecycle`: `active | baseline | archived`
- `RunManifest`
  - 实验 ID、run ID、Git commit/tag、dirty 状态
  - 完整 resolved config
  - 输入 artifact 引用与校验值
  - Python、PyTorch、CUDA、GPU、依赖锁摘要
  - 本地 PID、开始/结束时间、状态、退出码
  - 输出 artifact、checkpoint 和 metrics 路径
- `ArtifactRef`
  - `artifact_id`
  - `artifact_type`
  - `path`
  - `producer_run_id`
  - `schema_version`
  - `checksum`
  - `metadata`
- `RagSearchRequest` / `RagSearchResponse`
  - 统一约束检索类型、query image、top-k、ranker、权重、过滤条件和证据条目
  - HTTP 服务和进程内调用共用同一数据模型
- `StudentSftRecord`
  - 统一约束 messages、images、tools、sample ID、来源 artifact 和 schema version
- `EvaluationResult`
  - 统一保存样本结果、汇总指标、失败原因、评测协议版本和模型 artifact 引用

契约采用显式版本，例如 `agrinet.rag.search/v1`、`agrinet.sft.student/v1`。边界处必须验证，内部函数不再传递未经约束的任意字典。

### 2.4 模块职责

Data：

- 负责 AgriNet 数据选择、抽样、配对、VLOOM teacher generation、SFT 转换和数据验证。
- VLOOM 作为 `TeacherDataProvider` 的实现接入，不允许上层直接依赖 VLOOM 内部 registry。
- 输出版本化数据 artifact，RAG 与 VLM 只通过 `ArtifactRef` 消费。

RAG：

- 负责 SigLIP2 编码、Milvus schema/index、检索策略、HTTP 服务、工具调用蒸馏和 evidence gate。
- 检索核心实现与 HTTP handler 分离；单元测试可直接调用 `RetrievalService.search()`。
- 蒸馏 runner 拆成 teacher client、tool executor、trajectory policy、validator、artifact writer，不再由一个超长脚本同时承担所有职责。
- RAG 评测只能依赖公开的 tool contract 和 service client，不得从 distill runner 导入内部函数。

VLM：

- 负责 SFT 配置解析、ms-swift 调用、checkpoint 导出、Transformers/SGLang 推理与评测。
- `MsSwiftAdapter` 和 `VLMEvalKitAdapter` 是唯一允许接触 vendor 框架的项目接口。
- 训练、导出和评测使用统一 `ArtifactRef`，禁止通过 glob 猜测“最新 checkpoint”。

Vendor：

- 将两个 git subtree 移至 `vendor/`。
- 保留当前 subtree 更新历史与来源说明。
- 项目补丁进入 `patches/ms-swift` 并记录适用上游提交、目的和验证方式。
- 当前 SGLang multimodal 参数适配必须进入显式补丁队列，不再作为无说明的 vendor 内直接修改。
- CI 验证补丁可应用，adapter 测试验证项目接口不依赖非必要的上游内部符号。

## 3. 实验、命名与产物规范

### 3.1 实验注册

每个可运行实验对应一个短 YAML，例如：

```text
configs/experiments/rag/rag-distill-candidate-followup-v6.yaml
configs/experiments/vlm/vlm-sft-rag-qwen3vl4b-full-v1.yaml
configs/experiments/vlm/vlm-eval-rag-qwen3vl4b-sglang-v1.yaml
```

实验文件引用共享 component 配置，不复制所有参数：

```yaml
id: vlm-sft-rag-qwen3vl4b-full-v1
display_name:
  en: Qwen3-VL-4B full SFT on validated RAG trajectories
  zh: 基于已验证 RAG 轨迹的 Qwen3-VL-4B 全参数微调
domain: vlm
task: sft
lifecycle: baseline
components:
  model: models/qwen3-vl-4b-instruct
  data: data/rag-student-single-image-v1
  runtime: runtime/a800-4gpu-train
parameters:
  max_length: 8192
  epochs: 8
  learning_rate: 1.0e-5
  tuner: full
```

实验 ID 规则：

```text
<domain>-<task>-<subject>-<model-or-method>-<variant>-v<major>
```

规则：

- 全部使用小写英文 kebab-case。
- 名称描述研究意图，不编码日期、job ID、checkpoint step、学习率或 epoch。
- 超参数进入配置和 manifest。
- `final`、`latest`、`new`、`retry` 等含义不稳定的词禁止进入实验 ID。
- 行为或数据契约变化才提升版本；单纯重跑不新增实验版本。

Run ID 规则：

```text
YYYYMMDDTHHMMSS-<git-short-sha>-aNN
```

本地 PID 记录在 manifest，不作为实验名。

### 3.2 输出布局

新运行统一写入：

```text
outputs/runs/<domain>/<experiment-id>/<run-id>/
├── manifest.yaml
├── config.resolved.yaml
├── status.json
├── metrics.json
├── artifacts/
└── logs/
```

稳定、可被其他实验复用的产物登记到：

```text
outputs/artifacts/<artifact-type>/<artifact-id>/
```

包括：

- 数据集与 SFT JSONL
- Milvus Lite DB 和索引元数据
- 模型 checkpoint 或导出模型
- 评测 manifest 与指标摘要

本地后台进程 stdout/stderr 保存在：

```text
outputs/runs/<domain>/<experiment-id>/<run-id>/logs/stdout.log
outputs/runs/<domain>/<experiment-id>/<run-id>/logs/stderr.log
```

程序日志和可复用 artifact 不得混为一类；历史 `slurm/` 日志保留为迁移前记录。

## 4. 实施阶段

### 阶段 0：计划审阅

- 把本计划原样写入 `docs/refactor-20260803.md`。
- 在文档顶部标记 `Status: Draft for review`。
- 不实施代码或目录变更。
- 用户审阅通过后，将状态改为 `Approved`，再开始后续阶段。

### 阶段 1：基础设施与契约

- 增加根 `pyproject.toml`、Typer CLI、src-layout 和 uv lock。
- 单一 `.venv` 作为项目环境，不再使用 Conda 绝对路径、`.venv-py312` 或临时环境名。
- 定义实验、run、artifact、RAG search、student SFT 和 evaluation 契约。
- 实现配置加载、分层合并、override、路径解析和 manifest 写入。
- 增加 `agrinet data|rag|vlm list/show`，先验证注册表可读性。

### 阶段 2：Data 迁移

- 将 AgriNet 数据准备、验证、SFT 转换和 VLOOM adapter 迁入 `src/agrinet/data`。
- 把现有 data/VLOOM 配置转换为共享 component 与少量有效实验。
- 建立 teacher provider 接口，使 VLOOM 依赖停留在 adapter 内。
- 删除对应旧 shell/Slurm 入口；Data 长任务统一由本地运行器管理。
- 旧实验只登记有效、baseline 或仍需复现的配置，其余由 Git 历史保留。

### 阶段 3：RAG 迁移

- 提取 Milvus 编码、索引和检索服务为可测试库接口。
- 将 HTTP API 改为薄 transport 层，并保持现有 `/health` 和 `/search*` 行为的契约测试。
- 拆分 RAG distill runner，保留当前 evidence-gated 和 candidate-followup 行为。
- 将散落的多份 RAG `.slurm` 合并为实验配置加本地运行 profile。
- 建立 `agrinet rag index/search/serve/distill/validate/submit`。
- 删除旧 `tools/milvus`、`tools/rag_distill` 和重复调度入口。

### 阶段 4：VLM 迁移

- 建立 ms-swift 与 VLMEvalKit adapters。
- 将 SFT YAML 转成 model/data/runtime components 与可读实验配置。
- 建立显式 train、export、evaluate 流程，禁止自动 glob 最新 checkpoint。
- 把 SGLang RAG 评测编排拆成服务生命周期管理、推理和评分三个模块。
- 建立 VLM 本地前台/后台运行入口。
- 删除旧 `vlm/sft/configs` 中重复配置和 `scripts/vlm` 旧入口。

### 阶段 5：历史产物迁移

- 先生成 `outputs/migration/refactor-20260803.manifest.yaml`，列出源路径、目标路径、大小、checksum 和引用方。
- 只迁移当前文件系统中实际存在的产物；日志中存在但磁盘缺失的产物标记为 `unavailable`，不得伪造或盲建空目录。
- 使用 staging 目录复制约 8.3 GB 的 VLM baseline 和现有 Milvus 数据。
- 校验文件数量、总字节数、checksum、模型加载和 Milvus collection 后原子切换到新目标目录。
- 所有新代码和当前文档只引用新路径。
- 原路径保留为迁移备份直至完整验收；验收完成后删除，不创建兼容 symlink。
- 在 `docs/migrations/refactor-20260803.md` 保存旧路径到新 artifact ID 的映射。
- 历史研究日志保持原始语义，不批量改写；在主入口和迁移索引中说明其路径属于迁移前布局。

### 阶段 6：文档与清理

- 完成根 `README.md` 和 `README_CN.md`，展示三条主线和最短可运行命令。
- 为 data、rag、vlm 各维护一对 README。
- 更新 `docs/logs/START_HERE.md`，使其只描述当前主线、baseline 和新入口，不再充当长篇历史记录。
- 旧重复配置和入口登记后删除，不建立 archive 执行目录。
- 完成全仓旧路径、旧命令、Conda 绝对路径和裸 `PYTHONPATH` 引用扫描。
- 在重构验收后创建新的 milestone commit/tag；不移动或重写已有 baseline tag。

## 5. 环境、测试与验收

### 5.1 环境基线

目标环境：

- Python 3.12
- 项目根 `.venv`
- uv 管理与 `uv.lock`
- PyTorch CUDA 13.0 build
- NVIDIA A800 SM80
- NVIDIA driver 580 或更高
- 当前训练默认使用 SDPA、BF16、Liger 和 DeepSpeed ZeRO-3
- 传统 `flash_attn_func` 不属于 baseline 必需依赖
- SGLang/FlashInfer 作为 VLM eval 依赖组，并单独执行 GPU smoke

依赖按 extras 分组：

```text
core
data
rag
vlm-train
vlm-eval
dev
```

增加只读环境检查：

```bash
agrinet vlm doctor
agrinet rag doctor
agrinet data doctor
```

检查解释器路径、锁文件一致性、关键导入、CUDA/driver、GPU capability、模型/数据路径和可选后端。

### 5.2 自动化测试

单元测试：

- 实验 ID 和 run ID 命名校验
- 分层配置解析、override 和 resolved config
- manifest 与 artifact schema 序列化
- RAG search request/response
- evidence gate、名称泄漏和 student SFT validator
- checkpoint 与 artifact 解析
- adapter 不泄漏 vendor 内部接口

CLI 测试：

- 根命令和所有一级/二级 subcommand 的 `--help`
- 无效实验 ID、缺失 artifact、非法 override 的明确错误
- `list/show` 输出同时包含英文 ID 与中英文展示名
- `submit` dry-run 能生成确定的本地命令且不泄露凭据

集成测试：

- 小型数据 fixture：prepare → validate → convert
- mock teacher：RAG distill → evidence validation → student artifact
- Milvus Lite fixture：index → health → search
- VLM fixture：实验解析 → adapter 命令生成 → manifest
- 输出失败时 status 必须为 failed，已有产物不得被误标为 complete

GPU/本地运行 smoke：

- A800 上执行 BF16 CUDA 运算。
- 2-step VLM SFT smoke，验证 SDPA、Liger、ZeRO-3 和 checkpoint 写入。
- Milvus/SigLIP2 GPU 查询 smoke。
- SGLang/FlashInfer 启动并完成一条多模态推理。
- 验证本地进程退出码为 0、状态为 `complete`，并检查 run 目录日志。

迁移验收：

- baseline 权重迁移前后 checksum 一致。
- 新路径可由 Transformers/ms-swift adapter 加载。
- baseline manifest 能追溯到 tag、数据 artifact 和原 checkpoint。
- Milvus DB collection 数量和行数一致。
- 仓库中不存在仍被主文档或活动配置引用的旧路径。
- 当前入口不存在旧 Conda 绝对解释器路径、`.venv-py312` 或业务逻辑型调度脚本。

最终完成标准：

- 新用户仅阅读根 README 即可找到 data、rag、vlm 三个入口。
- 每个活动实验可通过 `agrinet <domain> list/show/submit` 发现、理解和运行。
- 每个运行目录都有 resolved config、manifest、状态和明确产物。
- 所有对外模块接口有类型、契约版本和测试。
- 当前 RAG SFT baseline 在新路径可加载、可评测、可追溯。
- 旧入口已删除且没有兼容层；历史路径通过迁移文档可查。

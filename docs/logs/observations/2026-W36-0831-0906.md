## 2026-09-03 14:24:00 CST - English error versus canonical-name strictness

### Note

Further split Direct-Only English test failures without changing the live queue.
Among 1,019 test rows, 974 have a nonempty final answer and no protocol error.
Of those, 303 answers exactly match some frozen catalog canonical name; only 82
match the true class, so at least 221 rows are definite wrong-class decisions,

Canonical strictness is nevertheless material.  The scorer has no alias table:
the frozen catalog exposes only one English and one Chinese name per code.  In

alternatives such as a common pest name where the catalog uses a Latin name.
The model is therefore trained on a noncanonical English target roughly one
fifth of the time while being evaluated by exact canonical matching.

String-only diagnostics flag 38 nonexact English answers containing the target
name and 103 with at least 0.70 normalized character similarity, but these are
not promoted to correct: some are genuinely broader or different diseases.
An authoritative per-class alias table plus human validation is required before
reporting an alias-tolerant secondary metric.

### Status

Verified: English accuracy reflects both substantial classification error and a
real, asymmetric English target/canonical-name contract defect.  It is invalid
to claim either "all English errors are naming variants" or "strict naming
has no effect".

### Next

Keep strict canonical accuracy as the current frozen primary result; construct
and review an alias map before publishing any secondary semantic/alias-tolerant
score.

## 2026-09-03 16:10:00 CST - Direct+RAG Chinese collapse is a supervision-contract defect

Tags: open-agri-v2, direct-rag, hermes, chinese, data-contract

### Note

Audit the frozen Direct+RAG training view and paired RAG test trajectories after
the completed model showed English RAG gains but Chinese RAG collapse.  The
active Direct×3+RAG training process was not changed.

### Status

- Verified root cause: Direct Chinese Open targets are 176/177 Chinese, but
  RAG Chinese Open targets are only 61/366 Chinese; 305/366 (83.3%) are
  English/non-Chinese final answers despite a Chinese user prompt.  The view
  renderer rewrites only system/user messages and preserves this historical
  assistant target.
- The RAG evaluator's private strict scorer expects Chinese canonical names for
  every `language=zh` row.  In test-ZH, 866/1,019 final answers are non-Chinese
  and score 0/866; only 153 Chinese answers occur, with 58 correct.  This
  directly explains the 5.69% Chinese RAG result and invalidates a bilingual
  capability comparison for this SFT view.
- Actual retrieval is live (test EN/ZH tool use 971/1,019 and 973/1,019).
  Paired samples show language-conditioned visual queries can produce different
  Top-1 hits, but this is secondary to the final-answer language contract
  failure.
- Secondary consistency defect: the RAG SFT view mixes two tool schemas (the
  generic schema on 665/726 EN and 670/730 ZH rows, and a long schema on the
  rest); evaluation uses the generic English schema.  The schema mix is nearly
  balanced by language, so it does not explain the EN/ZH reversal but must be
  canonicalized for a successor run.

### Next

Do not compare current Chinese RAG accuracy to English RAG as a method result.
For any rerun, construct a new immutable Open-only view that programmatically
canonicalizes every final `<answer>` from `class_code` to the required EN/ZH
catalog name, replaces every per-row tool schema with the exact evaluator
schema, and validates final-answer language/canonical equality before launch.

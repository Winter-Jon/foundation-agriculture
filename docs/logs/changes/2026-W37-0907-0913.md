## 2026-09-07 17:18:45 CST - Establish portable-mainline retention rule

Tags: repository-hygiene, reproducibility, retention-policy

### Note

The project rule is now explicit: the main repository retains only assets that
can be committed, migrated, and reused across checkouts—source, stable reusable
configuration, tests, compact documentation, and curated small evidence.

Keep machine-specific, credential-dependent, per-attempt, mutable, or bulky
state out of Git: runtime outputs and logs, checkpoints, downloaded datasets,
models, caches, retry/restart snapshots, and one-off queue or launcher scripts.
Place transient operational state under ignored local roots; use
`outputs/volatile/` when it is not a normal managed run output.

### Status

Recorded as the current repository retention convention. Existing ignored local
state is preserved; this rule does not authorize deleting any artifact.

### Next

Apply this classification before adding new files to Git.

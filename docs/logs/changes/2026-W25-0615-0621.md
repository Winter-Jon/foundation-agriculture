# Changes - 2026-W25 (0615-0621)

## 2026-06-15 09:02:42 CST - Require neutral candidates before name lookup

### Context
The prior candidate-name-verification strategy improved acceptance, but it still wrote an exact database name such as `Cherry Normal leaf` into a `name` tool call before that exact name appeared in real retrieval evidence. The latest requirement is stricter: before `name` lookup, the trajectory should use neutral candidate descriptions, and exact names are allowed only when copied from retrieved evidence.

### Changes
- Updated `src/agrinet/rag/distill/run_pilot.py` prompt version to `agrinet_rag_toolcall_v5_neutral_candidate_retrieved_name_only_private_gt`.
- Removed the allowance for post-retrieval exact private candidate-label lookup. `name_query_allowed()` now allows only exact names already present in retrieved tool evidence.
- Replaced the automatic private-label `name` verification follow-up with a neutral `balanced` follow-up generated from generic visible terms such as `leaf`, `healthy`, `normal`, `spot`, or task-domain symptoms.
- Updated `pre_tool_think()` for `name` calls to say the exact database name was copied from retrieved evidence.
- Added `neutral_rationale()` and rationale scrubbing so target-like terms in tool-call `rationale` are also replaced, not only the `query` field.
- Updated `src/agrinet/rag/distill/schema.py` so `name` retrieval is documented as exact lookup only for class names or aliases already present in retrieved evidence.
- Extended `src/agrinet/rag/distill/name_eval_smoke.py` to assert that unsupported exact names after visual retrieval are clamped away and that target-like rationale text is neutralized.

### Validation
- `python -m agrinet.rag.distill.name_eval_smoke` passed.
- Slurm job `19469` ran the first neutral-candidate rerun and produced `0` accepted / `5` rejected trajectories with `14/14` successful retrieval calls; validation failed only because accepted rows were empty.
- Slurm job `19470` reran after rationale scrubbing and again produced `0` accepted / `5` rejected trajectories with `14/14` successful retrieval calls. Validation failed only because accepted rows were empty.
- Scan over `outputs/rag_distill/agrinet_rag_toolcall_v5_neutral_candidate_rationale_clean_rerun_20260615_084745/train` and `traces/retrieval_calls.jsonl` found no unsupported `Cherry Normal leaf`, `N04029`, constructed evidence strings, `appeared in evidence`, or `domain hint` strings.

### Impact
- The current generator now satisfies the stricter policy: unsupported exact target names are not used for `name` lookup and are scrubbed from visible tool-call rationale text.
- The stricter policy exposes the underlying retrieval weakness: with `top_k=3` and neutral queries, the current dense retrieval rarely returns `Cherry Normal leaf`, so this latest run produces no training-ready accepted SFT rows.

### Next
- Add teacher timeout retries.
- Improve retrieval for neutral healthy/normal leaf queries before scaling.
- Do not use job `19468` as the current recommended SFT source under the stricter policy, because it intentionally used exact private candidate-name verification before the exact name appeared in evidence.

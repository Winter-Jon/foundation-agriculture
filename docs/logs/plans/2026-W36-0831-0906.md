# Plans — 2026-W36 (0831–0906)

## 2026-08-31 17:00:30 CST - M1 Direct 重建的可归因提升路线

Tags: m1-direct, direct-only, ablation, option-closure, capacity

### Goal
在不混入 RAG 的前提下，恢复并超过当前 terminal-v5 Direct-only 的表现，逐项解释相对 M1 的差距。

### Steps
1. 固定 terminal-v5 的图像、样本 ID、答案、训练预算和 Direct-618 manifest，仅比较 v1 与 user-guidance v3，验证题型说明从 `<think>` 移至 user 是否改善 Option closure。
2. 用同一图像和长链 reasoning 做视图组成消融：Open-only、Option-only、当前四视图；确认 Option 行是增益、无效，还是干扰 Open/最终字母闭合。
3. 设计一个保持 Direct contract 的 Option closure 强化视图或 loss 权重实验；不允许把正确字母或映射泄漏到 user/think。
4. 以严格隔离继续补齐 217×5，并为同一图像跨视图轮换 hard negatives，增加独立图像和候选组合多样性。
5. 对中文、disease、known/unknown 及 Open/Option 交叉薄弱格子平衡采样和单独 gate；比较采用 M1 的 4-GPU/global batch 64、2,048/delete 参数与当前 8-GPU/global batch 128、16,384/left 的独立优化消融。

### Acceptance
- 每个实验只改变一个主变量，并有 immutable data/model/run ID。
- 每个 checkpoint 得到 618 条唯一原生 Direct 预测、完整 metrics、10,000 paired bootstrap 与 known/unknown 分组。
- 选择不依赖 training loss：整体不低于 raw base，主要子集不超过预设退化阈值，并报告相对 M1 的差异。
- 只有 Direct-only 达标后，才进入 RAG 混合比例或初始化讨论。

### Risks
- 低训练 loss 不能作为 Option closure 成功的代理；字母 token 在长 reasoning后的 loss 权重很低。
- 现有 4,076 行只对应 1,019 独立图像、216 类，仍短 66 图且 N04080 缺失；行数增加不能替代独立视觉容量。
- known/unknown 是评测的稀有类划分，而不是当前 SFT 是否含该类别；两种解释不能混用。

### Next
先执行 v1 vs v3 的同预算、同 checkpoint schedule Direct-only 消融；其余变量全部锁定。

## 2026-09-02 00:00:48 CST - 科研可复现性与人工审阅仓库整理规划

Tags: repository-organization, reproducibility, documentation, experiment-registry

### Goal
在不改变当前研究结论、不移动运行中任务、也不删除历史证据的前提下，将项目整理为可由研究者快速审阅、由新成员可复现运行、由后续代理可安全维护的结构。

### Steps
1. 建立单一项目入口：重写根 `README.md`/`README_CN.md` 为项目地图，明确当前主线、正式评测入口、快速开始、目录语义与归档边界；继续以 `docs/logs/START_HERE.md` 为动态研究状态的唯一来源。
2. 建立面向论文与复现的“当前证据包”：以 `docs/results/CURRENT_FORMAL618_EVALUATION.md` 为结果唯一入口，补齐方法、数据谱系、固定协议、模型/配置、运行和原始产物之间的可点击索引；历史对比只保留在 `docs/archive/`。
3. 整理实验注册表：为 `data`、`rag`、`vlm` 的当前 experiment YAML 建立人可读清单，按主线/阶段/状态（current、control、deprecated、archive）标记；先做清单和迁移映射，确认引用后才移动过时配置。
4. 整理代码与脚本入口：为 `src/agrinet/`、`tools/`、`scripts/`、`vlm/`、`vision/` 和 `vendor/` 标注职责、受支持入口与历史/供应商边界；将可执行工作流优先收敛到 `agrinet`，对仍需保留的独立脚本提供用途、输入/输出和替代入口说明。
5. 规范数据、模型与产物：定义 dataset/model/run/artifact 的命名、最小元数据和保留状态；为 247GB `outputs/` 创建机器可检验的清单与保留/归档/待人工审批分类。所有删除、压缩或跨目录移动均在引用扫描、清单审计和用户批准后单独执行。
6. 增加质量门禁：为文档链接、实验 YAML schema/注册完整性、配置到运行目录的可追溯性、结果证据完整性和 archive 无误引用建立轻量检查；把检查纳入现有测试或独立只读审计命令。
7. 分批迁移与验收：每批只涵盖一个域，先新增兼容索引/重定向，再更新引用，最后做链接、CLI dry-run、目标测试和 Git diff 检查；产生迁移记录及可回滚清单。

### Acceptance
- 新读者可在 10 分钟内找到：研究问题、当前正式结论、复现实验、配置、数据/模型前提、原始证据及历史材料。
- 每个当前实验有唯一 ID、目的、状态、输入、配置、输出位置、评测协议和复现命令；每份结果可逆向定位到 immutable 数据/模型/运行证据。
- 当前、对照、已弃用和归档资源不会在导航中混淆；旧路径在迁移期内可发现或有明确映射。
- 不删除 checkpoint、数据、预测或历史日志，除非已有逐项清单、无引用证明及单独批准；运行中任务和共享输出不被移动。
- 自动检查通过，关键 CLI dry-run 与相关测试通过，文档链接无失效，研究日志记录每个可验证的迁移结论。

### Risks

- 当前 `main` 比 `origin/main` 超前 100 个提交；整理应保持小而主题明确的提交，避免将本地研究历史意外重写或混入同步操作。

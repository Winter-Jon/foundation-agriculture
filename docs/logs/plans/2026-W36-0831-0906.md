# Plans — 2026-W36 (0831–0906)

## 2026-08-31 17:00:30 CST - M1 Direct 重建的可归因提升路线

Tags: m1-direct, direct-only, ablation, option-closure, capacity

### Goal
在不混入 RAG 的前提下，恢复并超过当前 terminal-v5 Direct-only 的表现，逐项解释相对 M1 的差距。

### Steps
1. 固定 terminal-v5 的图像、样本 ID、答案、训练预算和 Direct-618 manifest，仅比较 v1 与 user-guidance v3，验证题型说明从 `<think>` 移至 user 是否改善 Option closure。
2. 用同一图像和长链 reasoning 做视图组成消融：Open-only、Option-only、当前四视图；确认 Option 行是增益、无效，还是干扰 Open/最终字母闭合。
3. 设计一个保持 Direct contract 的 Option closure 强化视图或 loss 权重实验；不允许把正确字母或映射泄漏到 user/think。
4. 以严格隔离继续补齐 217×5，并为同一图像跨视图轮换 hard negatives，增加独立图像和候选组合多样性。
5. 对中文、disease、known/unknown 及 Open/Option 交叉薄弱格子平衡采样和单独 gate；比较采用 M1 的 4-GPU/global batch 64、2,048/delete 参数与当前 8-GPU/global batch 128、16,384/left 的独立优化消融。

### Acceptance
- 每个实验只改变一个主变量，并有 immutable data/model/run ID。
- 每个 checkpoint 得到 618 条唯一原生 Direct 预测、完整 metrics、10,000 paired bootstrap 与 known/unknown 分组。
- 选择不依赖 training loss：整体不低于 raw base，主要子集不超过预设退化阈值，并报告相对 M1 的差异。
- 只有 Direct-only 达标后，才进入 RAG 混合比例或初始化讨论。

### Risks
- 低训练 loss 不能作为 Option closure 成功的代理；字母 token 在长 reasoning后的 loss 权重很低。
- 现有 4,076 行只对应 1,019 独立图像、216 类，仍短 66 图且 N04080 缺失；行数增加不能替代独立视觉容量。
- known/unknown 是评测的稀有类划分，而不是当前 SFT 是否含该类别；两种解释不能混用。

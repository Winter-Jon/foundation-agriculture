  ## 1. 总目标

  建立并持续执行 AgriNet RAG SFT 的协议优先迭代流程：

  1. 构造小规模 Pilot。
  2. 调用真实 Milvus RAG 生成轨迹。
  3. 严格拒绝采样。
  4. 审阅语言、答案、检索证据和标签边界。
  5. 通过 gate 后冻结训练语料。
  6. 从 retained non-RAG checkpoint-165 初始化进行 RAG SFT。
  7. 在关闭 forced retrieval 的条件下进行分级 Milvus RAG 评测。
  8. 与 checkpoint-165 的正式 618 条非 RAG 基线 65.21% 对比。

  轨迹规范优先级高于模型性能。不得为了提高接受率或准确率放宽：

  - 真实 Milvus evidence 支持；
  - 自主工具调用；
  - 中文、英文语言隔离；
  - Oracle/Blind 私有标签边界；
  - Open/Option 答案契约；
  - 数据与图像去重；
  - 训练集和评测集隔离；
  - 未知类泄漏检查；
  - 工具调用合法性；
  - 语义质量要求。

  正式 618 条评测、显著扩大采样预算及跨越硬 gate 均需暂停审批。

  ## 2. 里程碑 SFT 策略

  里程碑 SFT 是低频但可重复的迭代验证，不限制为整个项目只能运行一次。

  当前约束：

  - 每个发生实质性改进、通过审阅并冻结的数据版本可以运行一次里程碑 SFT。
  - 同一个 freeze hash 不重复训练。
  - 仅改变随机种子或超参数，不算新的数据里程碑。
  - 默认最多进行三个里程碑 SFT 后触发一次策略审阅；这是软预算，不是永久上限。
  - 连续两个里程碑验证失败，应提前回到 Pilot 和数据构造阶段。
  - 每次里程碑使用完整的、通过门控的冻结训练集。
  - 初始化权重是 retained non-RAG checkpoint-165。
  - 里程碑评测采用 forced retrieval 关闭的分级评测。
  - 正式 618 条评测仍需要单独审批。
  - 性能提升不能抵消任何轨迹协议错误。

  ## 13. Codex 工具路由异常

  旧线程曾频繁把预期的统一执行工具错误路由为：

  collaboration__list_agents

  表现：

  - 连续出现只读 agent list；
  - 没有启动子代理；
  - 没有项目副作用；
  - 一度阻止 shell、apply_patch 和 goal 更新；
  - 后来统一执行入口曾短暂恢复；
  - 新线程也可能继承同一客户端工具路由缓存。

  不要删除运行中的以下文件：

  - ~/.codex/state_5.sqlite
  - ~/.codex/state_5.sqlite-wal
  - ~/.codex/goals_1.sqlite
  - ~/.codex/goals_1.sqlite-wal
  - 当前 thread writer lock

  直接删除可能损坏 goal 或线程状态。

  如果异常复现：

  1. 不重复调用协作查询；
  2. 使用统一执行入口；
  3. 若持续失败，完全退出 Codex 客户端；
  4. 备份状态数据库后再进行客户端级排障；
  5. 重启客户端并创建非 team/collaboration 线程；
  6. 不要把该问题误判为项目或 API transport failure。
